# S06.5 · Sandbox lifecycle guarantees

- **Epic:** E06 · Sandbox Platform 2.0 (Phase 3: Core Features — MVP Hardening)
- **Priority:** P0 · **Effort:** 3 story points
- **Depends on:** S06.1
- **Repos:** backend
- **Suggested tech / approach:** K8s controller / cron job

## Description

TTL reaper, orphan detection and cost-safe teardown.

## Acceptance criteria (story)

- [ ] Reaper kills any sandbox older than TTL
- [ ] Orphan metric alerts when > 0 for 10 min
- [ ] Teardown is idempotent

## Tasks

### S06.5.1 · TTL labels + reaper job

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Runs every minute.
- **Done when:** Orphaned pod removed within TTL+1 min

### S06.5.2 · Orphan metrics & alert

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Prometheus metric; wired into central alerting by S23.2.
- **Done when:** Alert fires in staging test

## Epic context

Make the sandbox reproducible for real-world stacks: auto environment build, service dependencies, resource and network limits, artifact capture and guaranteed cleanup.

Epic acceptance criteria:

- Demo + 3 external open-source repos (Python, Node, Java) run without manual setup beyond riven.yaml
- No sandbox outlives its TTL
- Egress denied by default

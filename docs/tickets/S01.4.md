# S01.4 · Production data layer

- **Epic:** E01 · Production Architecture & Service Foundation (Phase 1: Foundation & Infrastructure)
- **Priority:** P0 · **Effort:** 5 story points
- **Depends on:** S01.1
- **Repos:** backend
- **Suggested tech / approach:** Alembic, PostgreSQL 16 (graph as node/edge tables), S3/MinIO

## Description

Harden persistence: migrations, tenant-ready schema, artifact storage, graph DB sync.

## Acceptance criteria (story)

- [ ] All schema changes via migrations
- [ ] Logs/artifacts moved off local disk to object storage
- [ ] Graph node/edge tables consistency check reports zero orphaned edges on the demo repo

## Tasks

### S01.4.1 · Introduce Alembic migrations for all MVP tables

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Baseline migration from current schema.
- **Done when:** Fresh DB reaches head via migrations only

### S01.4.2 · Add tenant_id / org_id to all domain tables (nullable→backfilled)

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)

- **What to do:** Prepares for multi-tenancy (S03.2).
- **Done when:** All domain tables have indexed org_id

### S01.4.3 · Move sandbox logs and artifacts to object storage

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Presigned URLs for download.

### S01.4.4 · Graph tables + consistency checker

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)

## Epic context

Refactor the MVP monolith/scripts into clearly bounded services with durable workflow orchestration, an event backbone and a production data layer, so every later epic can be built without re-architecture.

Epic acceptance criteria:

- Service boundaries documented in ADRs and reflected in the repo layout
- The full MVP 15-step scenario runs on the new architecture with no functional regression
- Pipeline survives a worker crash mid-run and resumes without duplicate side effects

# S01.1 · Define service boundaries & internal contracts

- **Epic:** E01 · Production Architecture & Service Foundation (Phase 1: Foundation & Infrastructure)
- **Priority:** P0 · **Effort:** 5 story points
- **Depends on:** B01
- **Repos:** backend
- **Suggested tech / approach:** Monorepo (uv workspaces + pnpm), Pydantic v2, JSON Schema

## Description

Split the platform into logical services: api-gateway, capture, orchestrator, sandbox-runner, verifier, memory, graph, web. Define versioned contracts between them.

## Acceptance criteria (story)

- [ ] ADR per service boundary merged
- [ ] Every inter-service payload has a versioned Pydantic schema published as JSON Schema
- [ ] Contract tests fail on a breaking schema change

## Tasks

### S01.1.1 · Write ADRs for service decomposition and data ownership

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** One ADR per service: responsibility, owned tables, published events.
- **Done when:** ADRs reviewed and merged in /docs/adr

### S01.1.2 · Restructure repo into monorepo packages

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** S01.1.1
- **What to do:** apps/* for services, packages/* for shared libs (schemas, clients, logging).
- **Done when:** All services build and tests pass from repo root

### S01.1.3 · Create shared schema package for contracts & events

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** S01.1.2
- **What to do:** Pydantic models for Change, VerificationRun, Bug, RegressionLock, GraphEdge, domain events.
- **Done when:** Schemas exported as JSON Schema artifacts in CI

### S01.1.4 · Add contract tests between services

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** S01.1.3
- **What to do:** Schemathesis/pact-style tests on schema compatibility.
- **Done when:** CI fails on a backward-incompatible schema change

## Epic context

Refactor the MVP monolith/scripts into clearly bounded services with durable workflow orchestration, an event backbone and a production data layer, so every later epic can be built without re-architecture.

Epic acceptance criteria:

- Service boundaries documented in ADRs and reflected in the repo layout
- The full MVP 15-step scenario runs on the new architecture with no functional regression
- Pipeline survives a worker crash mid-run and resumes without duplicate side effects

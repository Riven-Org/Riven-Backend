# S05.4 · Requirement ingestion & auto-linking

- **Epic:** E05 · Change Capture & Understanding 2.0 (Phase 3: Core Features — MVP Hardening)
- **Priority:** P1 · **Effort:** 8 story points
- **Depends on:** S05.2, S09.1
- **Repos:** backend, frontend
- **Suggested tech / approach:** Markdown parser, pgvector embeddings, Claude API

## Description

Import requirements from repo docs (markdown/specs) and PR descriptions; auto-link changes to requirements with confidence and human confirmation.

## Acceptance criteria (story)

- [ ] Requirements imported from /docs or configured paths
- [ ] Explicit refs (REQ-123) linked deterministically
- [ ] Semantic suggestions shown with confidence; human confirms/rejects

## Tasks

### S05.4.1 · Requirement import from repo docs

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Headings → requirement nodes, stable IDs.
- **Done when:** Re-import is idempotent

### S05.4.2 · Explicit reference linker

- **Repo:** backend

### S05.4.3 · Semantic link suggester

- **Repo:** backend

## Epic context

Upgrade capture from basic commit/PR metadata to a GitHub App with semantic change analysis, provenance (human vs AI agent) and requirement linking.

Epic acceptance criteria:

- Capture latency < 30s from push to run start
- Function-level change map for supported languages
- ≥ 80% of PRs auto-linked to a requirement with confidence score

# S07.2 · Flaky test detection & quarantine

- **Epic:** E07 · Verification Engine 2.0 (Phase 3: Core Features — MVP Hardening)
- **Priority:** P0 · **Effort:** 5 story points
- **Depends on:** S07.1, S06.4
- **Repos:** backend, frontend
- **Suggested tech / approach:** Statistical flakiness score (fail/pass flips)

## Description

Automatic reruns on failure, flakiness scoring and quarantine so noise doesn't pollute bug memory.

## Acceptance criteria (story)

- [ ] Failed test auto-rerun N times (configurable)
- [ ] Flakiness score per test over history
- [ ] Quarantined tests reported separately, never create bugs

## Tasks

### S07.2.1 · Rerun-on-failure policy

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Isolated rerun of failed tests only.
- **Done when:** Pass-on-rerun marked 'flaky'

### S07.2.2 · Flakiness scoring job

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Rolling window.
- **Done when:** Score visible per test

### S07.2.3 · Quarantine list & UI

- **Repo:** both
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Manual + automatic.
- **Done when:** Quarantined failures excluded from verdict

## Epic context

Turn the verification engine into a pluggable, policy-driven system with flaky-test handling, human review workflow and enforced independence from the change producer.

Epic acceptance criteria:

- Verifiers can be added without changing the core pipeline
- Flaky tests never produce 'new bug' records
- Every verdict records producer and verifier identities, and they differ

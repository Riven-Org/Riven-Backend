# S02.2 · Environment & configuration strategy

- **Epic:** E02 · Environments, Developer Experience & IaC (Phase 1: Foundation & Infrastructure)
- **Priority:** P0 · **Effort:** 3 story points
- **Depends on:** S02.1
- **Repos:** backend
- **Suggested tech / approach:** pydantic-settings, AWS Secrets Manager or Doppler

## Description

dev / staging / prod separation, 12-factor config, secrets outside code.

## Acceptance criteria (story)

- [ ] No secrets in git (enforced by gitleaks in CI)
- [ ] Config validated at startup with typed settings
- [ ] Staging and prod have isolated accounts/projects

## Tasks

### S02.2.1 · Typed settings module per service

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Fail fast on missing config.
- **Done when:** Service refuses to start with invalid config

### S02.2.2 · Secrets manager integration

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Inject at runtime via env/CSI driver.
- **Done when:** Rotating a secret requires no code change

### S02.2.3 · Separate cloud accounts for staging/prod

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** AWS Organizations.

## Epic context

Give the team reproducible local/staging/prod environments, enforced code quality and infrastructure as code.

Epic acceptance criteria:

- New engineer runs the full stack locally in < 30 minutes
- Every PR runs lint, type check and tests
- Staging is fully reproducible from Terraform

# S08.3 · Automated reproduction capture

- **Epic:** E08 · Bug Memory & Regression Lock 2.0 (Phase 3: Core Features — MVP Hardening)
- **Priority:** P1 · **Effort:** 5 story points
- **Depends on:** S06.4, S08.2
- **Repos:** backend
- **Suggested tech / approach:** Sandbox re-run API

## Description

Store minimal reproduction: failing test id, inputs, env snapshot, seed; re-runnable in one click.

## Acceptance criteria (story)

- [ ] Repro bundle stored for every confirmed bug
- [ ] 'Re-run repro' reproduces failure on buggy commit
- [ ] Repro includes env/image digest

## Tasks

### S08.3.1 · Repro bundle model

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Test id, inputs, image digest, seed.
- **Done when:** Bundle saved on confirm

### S08.3.2 · One-click repro re-run

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Pins commit + image.
- **Done when:** Re-run reproduces on buggy commit

## Epic context

Scale bug memory from a single module to the whole repo: fingerprinting, lifecycle, automated repro, regression locks for all confirmed bugs and smart lock selection.

Epic acceptance criteria:

- Recurring bugs detected with ≥ 90% precision on benchmark corpus
- Every confirmed+fixed bug gets a validated lock test (fails on buggy commit, passes on fix)
- Relevant locks run on every change in < 5 min p95

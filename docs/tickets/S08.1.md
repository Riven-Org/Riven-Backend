# S08.1 · Bug fingerprinting & deduplication

- **Epic:** E08 · Bug Memory & Regression Lock 2.0 (Phase 3: Core Features — MVP Hardening)
- **Priority:** P0 · **Effort:** 8 story points
- **Depends on:** S07.3
- **Repos:** backend, frontend
- **Suggested tech / approach:** Signature hashing + pgvector

## Description

Normalize errors (stack traces, messages) into fingerprints; combine with embedding similarity to detect recurring/duplicate bugs.

## Acceptance criteria (story)

- [ ] Same failure across commits maps to one bug
- [ ] Near-duplicates suggested with similarity score
- [ ] Recurring bugs flagged in verdict

### S08.1.2 · Fingerprint + embedding storage

### S08.1.3 · Dedup/merge UI

- **Repo:** both
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)

## Epic context

Scale bug memory from a single module to the whole repo: fingerprinting, lifecycle, automated repro, regression locks for all confirmed bugs and smart lock selection.

Epic acceptance criteria:

- Recurring bugs detected with ≥ 90% precision on benchmark corpus
- Every confirmed+fixed bug gets a validated lock test (fails on buggy commit, passes on fix)
- Relevant locks run on every change in < 5 min p95

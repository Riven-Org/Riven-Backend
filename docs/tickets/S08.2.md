# S08.2 · Bug lifecycle state machine

- **Epic:** E08 · Bug Memory & Regression Lock 2.0 (Phase 3: Core Features — MVP Hardening)
- **Priority:** P0 · **Effort:** 3 story points
- **Depends on:** S08.1, S04.4
- **Repos:** backend
- **Suggested tech / approach:** State machine (transitions lib)

## Description

New → Confirmed → Fixing → Fix Verified → Locked → Reopened (on recurrence), with audited transitions.

## Acceptance criteria (story)

- [ ] Invalid transitions rejected
- [ ] Recurrence automatically reopens a Locked bug
- [ ] Timeline of transitions on bug detail

## Tasks

### S08.2.1 · State machine + transition API

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Guards per role.
- **Done when:** Unit tests for all transitions

### S08.2.2 · Auto-reopen on recurrence

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Triggered by fingerprint match.
- **Done when:** Reopened bug notifies owner

## Epic context

Scale bug memory from a single module to the whole repo: fingerprinting, lifecycle, automated repro, regression locks for all confirmed bugs and smart lock selection.

Epic acceptance criteria:

- Recurring bugs detected with ≥ 90% precision on benchmark corpus
- Every confirmed+fixed bug gets a validated lock test (fails on buggy commit, passes on fix)
- Relevant locks run on every change in < 5 min p95

# S03.3 · Role-based access control

- **Epic:** E03 · Identity, Authentication & Authorization (Phase 2: Auth & Core Platform)
- **Priority:** P0 · **Effort:** 5 story points
- **Depends on:** S03.2
- **Repos:** backend, frontend
- **Suggested tech / approach:** Casbin or custom policy layer

## Description

Roles: Owner, Admin, Maintainer, Reviewer, Viewer, with a permission matrix enforced in API and UI.

## Acceptance criteria (story)

- [ ] Permission matrix documented
- [ ] Every endpoint declares required permission
- [ ] UI hides actions the user cannot perform

## Tasks

### S03.3.1 · Define permission matrix

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Actions × roles incl. confirm bug, approve review, create lock.
- **Done when:** Matrix approved by product

### S03.3.2 · Policy enforcement decorator on endpoints

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** S03.3.1
- **What to do:** Deny by default.
- **Done when:** Endpoint without declared permission fails CI check

### S03.3.3 · Role-aware UI

- **Repo:** frontend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** S03.3.2
- **What to do:** Permission hook in frontend.
- **Done when:** Viewer sees no mutation buttons

## Epic context

Introduce users, organizations, tenant isolation, roles and machine identities. Machine identities are what make 'who produced this change' provable, a prerequisite for Riven's independence principle.

Epic acceptance criteria:

- Every API call is authenticated and tenant-scoped
- Cross-tenant access attempts are denied (automated test)
- AI agents authenticate with scoped service tokens

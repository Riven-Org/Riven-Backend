# S03.1 · User sign-up and login

- **Epic:** E03 · Identity, Authentication & Authorization (Phase 2: Auth & Core Platform)
- **Priority:** P0 · **Effort:** 5 story points
- **Depends on:** S02.2
- **Repos:** backend, frontend
- **Suggested tech / approach:** Keycloak or WorkOS, authlib

## Description

Email + OAuth (GitHub, Google) login via an OIDC provider.

## Acceptance criteria (story)

- [ ] Users sign up/in with GitHub or Google
- [ ] Email verification required for email accounts
- [ ] JWT validated on every API request

## Tasks

### S03.1.1 · Deploy/configure identity provider

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Realm, clients, social IdPs.
- **Done when:** Login works in staging

### S03.1.2 · API JWT validation middleware

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** S03.1.1
- **What to do:** JWKS caching; audience/issuer checks.
- **Done when:** Invalid/expired tokens return 401

### S03.1.3 · Frontend auth flow (PKCE)

- **Repo:** frontend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** S03.1.1
- **What to do:** Login, logout, silent refresh.
- **Done when:** Session survives page reload; logout clears tokens

## Epic context

Introduce users, organizations, tenant isolation, roles and machine identities. Machine identities are what make 'who produced this change' provable, a prerequisite for Riven's independence principle.

Epic acceptance criteria:

- Every API call is authenticated and tenant-scoped
- Cross-tenant access attempts are denied (automated test)
- AI agents authenticate with scoped service tokens

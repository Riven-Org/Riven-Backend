# S04.4 · Core audit log

- **Epic:** E04 · Public API & Core Platform Services (Phase 2: Auth & Core Platform)
- **Priority:** P0 · **Effort:** 3 story points
- **Depends on:** S03.3
- **Repos:** backend, frontend
- **Suggested tech / approach:** Postgres append-only table, DB grants

## Description

Append-only record of every state change (who, what, when, before/after).

## Acceptance criteria (story)

- [ ] Every mutation endpoint writes an audit entry
- [ ] Audit log is queryable by admins
- [ ] Entries cannot be updated or deleted via the app role

## Tasks

### S04.4.1 · Audit middleware and table

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Actor, action, target, diff, IP.
- **Done when:** Mutation without audit entry fails test

### S04.4.2 · Audit log viewer (admin)

- **Repo:** both
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** S04.4.1
- **What to do:** Filter by actor/action/date.
- **Done when:** Admin can export filtered CSV

## Epic context

Expose Riven as a platform: versioned API, SDK/CLI, outbound webhooks, audit log, notifications and usage metering.

Epic acceptance criteria:

- Every dashboard capability is available via the public API
- Agents and CI can trigger verification with the CLI
- All state changes appear in the audit log

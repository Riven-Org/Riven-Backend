# S05.1 · GitHub App-based capture

- **Epic:** E05 · Change Capture & Understanding 2.0 (Phase 3: Core Features — MVP Hardening)
- **Priority:** P0 · **Effort:** 5 story points
- **Depends on:** S03.2
- **Repos:** backend
- **Suggested tech / approach:** GitHub App, webhook receiver

## Description

Replace PAT/polling with a GitHub App: installation flow, verified webhooks, history backfill.

## Acceptance criteria (story)

- [ ] Install flow links GitHub org to Riven org
- [ ] Webhook signatures verified; invalid ones rejected
- [ ] Backfill imports last 90 days of commits/PRs

## Tasks

### S05.1.1 · Register GitHub App & installation flow

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Minimal permissions.
- **Done when:** Installing app lists repos in Riven

### S05.1.2 · Webhook receiver with signature verification

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** S05.1.1
- **What to do:** push, pull_request, check_suite.
- **Done when:** Unsigned request returns 401

### S05.1.3 · History backfill job

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** S05.1.1
- **What to do:** Rate-limit aware.
- **Done when:** 90 days imported without hitting secondary rate limits

## Epic context

Upgrade capture from basic commit/PR metadata to a GitHub App with semantic change analysis, provenance (human vs AI agent) and requirement linking.

Epic acceptance criteria:

- Capture latency < 30s from push to run start
- Function-level change map for supported languages
- ≥ 80% of PRs auto-linked to a requirement with confidence score

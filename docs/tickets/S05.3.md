# S05.3 · Change provenance (human vs AI agent)

- **Epic:** E05 · Change Capture & Understanding 2.0 (Phase 3: Core Features — MVP Hardening)
- **Priority:** P1 · **Effort:** 3 story points
- **Depends on:** S03.4, S05.1
- **Repos:** backend, frontend
- **Suggested tech / approach:** Commit trailer parsing (e.g. Co-Authored-By), API key identity

## Description

Record who/what produced a change: human, AI agent (which tool/model), bot; via API key identity, commit trailers and bot accounts.

## Acceptance criteria (story)

- [ ] Provenance field set for 100% of changes (unknown allowed)
- [ ] Agent metadata (tool, model) stored when provided
- [ ] Filter dashboard by provenance

## Tasks

### S05.3.1 · Provenance detector

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Rules: API key > trailer > bot login > human.
- **Done when:** Unit tests cover each rule

### S05.3.2 · Agent metadata schema

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed

- **Done when:** Metadata visible on change detail

### S05.3.3 · Provenance filter in UI & API

- **Repo:** both
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Facet filter.
- **Done when:** Filter returns only matching changes

## Epic context

Upgrade capture from basic commit/PR metadata to a GitHub App with semantic change analysis, provenance (human vs AI agent) and requirement linking.

Epic acceptance criteria:

- Capture latency < 30s from push to run start
- Function-level change map for supported languages
- ≥ 80% of PRs auto-linked to a requirement with confidence score

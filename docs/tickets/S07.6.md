# S07.6 · Independence enforcement

- **Epic:** E07 · Verification Engine 2.0 (Phase 3: Core Features — MVP Hardening)
- **Priority:** P0 · **Effort:** 3 story points
- **Depends on:** S03.4, S07.1
- **Repos:** backend
- **Suggested tech / approach:** Policy check in workflow

## Description

Encode 'Riven never approves its own work': verifier identity ≠ producer identity; verification must not rely solely on producer-supplied tests; recorded per verdict.

## Acceptance criteria (story)

- [ ] Verdict blocked if producer == verifier identity
- [ ] Report shows proportion of checks independent of producer tests
- [ ] Independence metadata stored for attestation (S20.5)

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)

## Epic context

Turn the verification engine into a pluggable, policy-driven system with flaky-test handling, human review workflow and enforced independence from the change producer.

Epic acceptance criteria:

- Verifiers can be added without changing the core pipeline
- Flaky tests never produce 'new bug' records
- Every verdict records producer and verifier identities, and they differ

# S03.5 · Session security & MFA

- **Epic:** E03 · Identity, Authentication & Authorization (Phase 2: Auth & Core Platform)
- **Priority:** P1 · **Effort:** 3 story points
- **Depends on:** S03.1
- **Repos:** backend, frontend
- **Suggested tech / approach:** Identity provider MFA features

## Description

TOTP MFA, org-enforced MFA, session listing and revocation.

## Acceptance criteria (story)

- [ ] Users can enrol TOTP
- [ ] Org admins can require MFA
- [ ] Users can revoke other sessions

## Tasks

### S03.5.1 · Enable TOTP MFA in IdP

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Recovery codes.
- **Done when:** Login requires 2nd factor when enrolled

### S03.5.2 · Org-level MFA enforcement

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Policy flag.
- **Done when:** Non-MFA member is forced to enrol

### S03.5.3 · Session management page

- **Repo:** frontend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** List/revoke sessions.
- **Done when:** Revoked session gets 401 on next call

## Epic context

Introduce users, organizations, tenant isolation, roles and machine identities. Machine identities are what make 'who produced this change' provable, a prerequisite for Riven's independence principle.

Epic acceptance criteria:

- Every API call is authenticated and tenant-scoped
- Cross-tenant access attempts are denied (automated test)
- AI agents authenticate with scoped service tokens

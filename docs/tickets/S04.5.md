# S04.5 · Notification service

- **Epic:** E04 · Public API & Core Platform Services (Phase 2: Auth & Core Platform)
- **Priority:** P1 · **Effort:** 3 story points
- **Depends on:** S01.3
- **Repos:** backend, frontend
- **Suggested tech / approach:** Postmark/SES, in-app via SSE

## Description

In-app and email notifications for verdicts, recurring bugs, review requests, with user preferences.

## Acceptance criteria (story)

- [ ] User receives email on 'Needs Review' assignment
- [ ] Preferences per event type
- [ ] In-app notification centre

## Tasks

### S04.5.1 · Notification model + preference API

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Channels × events.
- **Done when:** Muted events are not sent

### S04.5.2 · Email templates & sender

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)

### S04.5.3 · In-app notification centre

- **Repo:** frontend

# S03.4 · Service accounts & API keys for AI agents / CI

- **Epic:** E03 · Identity, Authentication & Authorization (Phase 2: Auth & Core Platform)
- **Priority:** P0 · **Effort:** 5 story points
- **Depends on:** S03.3
- **Repos:** backend, frontend
- **Suggested tech / approach:** Argon2 hashed keys, prefix-based lookup

## Description

Scoped, rotatable tokens representing an agent or CI system; recorded as change producer identity.

## Acceptance criteria (story)

- [ ] Keys are hashed at rest and shown once
- [ ] Each key has scopes and optional expiry
- [ ] Changes submitted with an agent key record that agent as producer

## Tasks

### S03.4.1 · Service account + API key model

- **Repo:** backend
- **Size:** M (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** previous tasks in this story as needed
- **What to do:** Scopes, expiry, last-used.

### S03.4.2 · Key management UI

- **Repo:** frontend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** S03.4.1
- **What to do:** Create/rotate/revoke.

### S03.4.3 · Producer identity attached to Change records

- **Repo:** backend
- **Size:** S (S ≤ 1 day, M 2–3 days, L 4–5 days)
- **Depends on:** S03.4.1
- **What to do:** Human user / agent / bot.
- **Done when:** Change detail shows authenticated producer

## Epic context

Introduce users, organizations, tenant isolation, roles and machine identities. Machine identities are what make 'who produced this change' provable, a prerequisite for Riven's independence principle.

Epic acceptance criteria:

- Every API call is authenticated and tenant-scoped
- Cross-tenant access attempts are denied (automated test)
- AI agents authenticate with scoped service tokens

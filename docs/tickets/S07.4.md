# S07.4 · Human review workflow for 'Needs Review'

- **Epic:** E07 · Verification Engine 2.0 (Phase 3: Core Features — MVP Hardening)
- **Priority:** P0 · **Effort:** 5 story points
- **Depends on:** S07.3, S03.3, S04.5
- **Repos:** backend, frontend
- **Suggested tech / approach:** Workflow state machine, notifications

## Description

Gap in MVP: status exists but no workflow. Add review queue, assignment, approve/reject with rationale that feeds memory.

## Acceptance criteria (story)

- [ ] Needs Review runs appear in a review queue with assignee
- [ ] Reviewer decision + rationale stored and audited
- [ ] Rejections can be converted to confirmed bugs in one click

## Epic context

Turn the verification engine into a pluggable, policy-driven system with flaky-test handling, human review workflow and enforced independence from the change producer.

Epic acceptance criteria:

- Verifiers can be added without changing the core pipeline
- Flaky tests never produce 'new bug' records
- Every verdict records producer and verifier identities, and they differ
